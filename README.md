## 🤔 你受够了吗？

你用 AI 写代码，它给你一段能跑但不知道有没有 bug 的代码。你让它审自己的代码——**自己审自己，能审出什么？**

你让它写个大项目，跑着跑着上下文爆了，前面的设计决策全丢了。你让它改个东西，它忘了之前为什么那样写。

**一个人 + 一个 AI = 一个 AI 的偏见、盲区和上下文限制。**

## 🏢 我们的答案：直接开一家公司

牛马公司不是"AI 助手"，**它是一家完整的软件公司，运行在你的 Claude Code 里。**

你当老板，提需求。剩下的——组建团队、分配任务、写代码、Review、改 Bug、验收交付——全部自动完成。

## 🔥 为什么牛马公司不一样

| 别人 | 牛马公司 |
|------|----------|
| 一个模型自问自答 | **两个公司的模型交叉审查**（Claude 写，Codex 审） |
| 上下文爆了就失忆 | **文件中介系统**——中间产出全写磁盘，prompt 永远苗条 |
| 方案评审就完事 | **产出真实代码**——操作员写文件、跑测试、交验证报告 |
| 改了 N 轮不知道哪版能用 | **QA 严格打分**——不够 8 分打回去重做，最多 5 轮 ，取最高分 |
| 下次改同一个项目从头开始 | **后续迭代模式**——自动探查现有代码，增量修改 |
| 审方案 = 自己审自己 | **Codex 每次全新上下文**——不带偏见，审完即焚 |

## 🎯 核心亮点

### 🏛️ 真正的公司架构，不是聊天机器人

```
v1 时代的 AI 编程：你 → AI → 代码
牛马公司：          你 → 项目经理 → 主管(HR) → 组长 → 工程师 → QA → 交付
```

**五个阶段、三层汇报链、三个 QA 审计点。** 每个角色只做自己该做的事，没人能既当运动员又当裁判。

### 🔍 跨模型审查——Claude 写代码，Codex 挑毛病

这是牛马公司最硬核的设计。QA 审查员用 **Codex（OpenAI）**，和写代码的 Claude 是**完全不同的大脑**。

```
Claude 写的方案 → Codex 审计 → 不通过？打回去改
Claude 写的代码 → Codex 审查 → 有 bug？打回去修
Claude 的交付报告 → Codex 终审 → 不够 8 分？不准发给老板
```

**真正的 adversarial review，不是自欺欺人的"我审我自己"。**

### 📁 文件中介——上下文永远不会爆

传统的多 Agent 系统，每个 Agent 把结果塞进下一个 Agent 的 prompt——**三个 Agent 下来上下文就炸了。**

牛马公司用文件中介：每个 Agent 把产出写入磁盘，下一个 Agent 只收到**文件路径**，按需读取。

```
传统：Agent A → 塞 3000 字 → Agent B → 塞 5000 字 → Agent C → 💥
牛马：Agent A → 写文件 → 传路径 → Agent B → 按需 Read → 😌
```

**项目经理的上下文窗口永远干干净净，只有路径和摘要。**

### 🔄 天然的增量开发

第二轮改同一个项目？不需要重放上一轮的历史。

代码就是团队的"项目文档"。新主管开工前先 Read 项目结构，PROJECT.md 记录关键架构决策。**每次都是全新的独立任务，互不污染。**

### 🧯 崩溃恢复——随时保存，随时继续

上下文出问题了？说一句"保存进度"，STATE.md 记录所有断点。开新会话，一句"从 /tmp/se-task/ 恢复"，从断点继续。

## 🚀 30 秒开始

### 前提

- [Claude Code](https://claude.ai/code) 已安装
- [Codex CLI](https://github.com/openai/codex) 已安装并登录

### 安装

```bash
# 把牛马公司命令复制到 Claude Code 的 commands 目录
cp 牛马公司.md ~/.claude/commands/牛马公司.md
```

### 使用

```bash
# Claude Code 中直接调用
/牛马公司 做一个命令行待办事项工具，支持增删改查

# 或者在后续迭代
/牛马公司 在 /Users/me/my-blog 里加评论功能，支持匿名评论和回复

# 恢复中断
/牛马公司 从 /tmp/se-task/ 恢复
```

## ⚠️ 诚实说明

**这不是 AGI，不是魔法。** 它是一个精巧的多 Agent 编排系统：

- 它不能替代真正的软件工程师——它能加速 80% 的重复性工作，但复杂架构决策仍需你的判断
- Codex 审查 ≠ 人工 Code Review——它可能漏掉深层逻辑问题
- 大项目（20+ 文件）可能触发兜底机制（副总管分压），执行时间会更长
- 每次 QA 调用 Codex 需要网络和 API 配额

**适合：** 原型开发、小中型功能、重构任务、技术调研、代码审查

**不适合：** 操作系统内核、金融交易系统、任何不能容忍 AI 犯错的关键任务
