# 牛马公司 v4 设计文档

**日期**：2026-06-12
**版本**：v4.0
**类型**：架构升级

---

## 背景与动机

v3 在约 8 人任务规模下出现主窗口上下文爆炸，通常在 98% 进度（QA 审查循环两轮后、第三轮通过时）溢出。用户无法查看 Agent 上下文使用状态。同时 DeepSeek V4 Pro 的 1M 上下文窗口因配置问题未生效。

## 核心问题

1. **主窗口上下文爆炸**：QA REVISE 循环是最大上下文堆叠源
2. **Agent 状态不可见**：用户无法判断哪些 Agent 处于"窒息边缘"
3. **1M 上下文未生效**：`[1M]`（大写）不匹配 Claude Code 的 `[1m]` 检测

## 设计变更

### 1. 上下文预算分析（阶段一新增维度）

- 主管组建团队时，为每个操作员 + 自己预估上下文消耗
- 预算模型：预估 ≈ 任务描述 + 需读文件总量 + 产出文件总量 + 对话轮数预留
- 三级风险分类：🟢 ≤60% 安全 / 🟡 61-80% 临界 / 🔴 >80% 危险（禁止分配）
- 产出：`/tmp/se-task/00-context-budget.md`

### 2. 主管助理（常设角色）

- 每次任务默认配备，生命周期：阶段一招来 → 阶段四干一次活 → 阶段五解雇
- 职责：汇总各组 SUMMARY.md 为最终报告，不做决策、不改代码、不参与 QA
- 独立全新上下文，用完即弃
- 解决阶段四汇总的上下文峰值问题

### 3. 动态保护机制

- 症状检测：产出遗漏 / 质量崩塌 / 自感过载
- 保护流程：STOP → SAVE → REPORT → EXIT
- Checkpoint 断点存档：`/tmp/se-task/.checkpoint/{角色名}.md`
- 接替机制：项目经理读 checkpoint → 新建同名 Agent → 从断点继续

### 4. 状态仪表盘

- `/tmp/se-task/.status/{角色名}.status`：每个 Agent 一行状态
- 项目经理不主动展示，用户问才看
- 阶段切换时口头通报一行

### 5. REVISE 协调改造

- 主管（全新 Agent 上下文）负责读 QA 报告 + 判断 + 派组长
- 主管助理（全新）负责重新汇总

### 6. 前置修复

- `settings.local.json` 模型后缀 `[1M]` → `[1m]`（小写）
- Haiku 模型补充 `[1m]` 后缀
